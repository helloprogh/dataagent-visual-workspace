先启动 OpenCode V2，在运行环境中设置 `OPENCODE_BASE_URL`、`OPENCODE_PASSWORD`（如服务要求认证）和可选 `OPENCODE_WORKSPACE_DIRECTORY`，然后运行：

```powershell
node scripts/live-session-smoke.mjs
```

此命令启动临时本机 Adapter，调用真实上游，不使用 mock。会创建一条 `UI live check` 测试会话和一个小型文本附件；不会调用模型、删除会话或修改工作区业务文件。结束后关闭临时 Adapter，保留测试会话便于复核。凭据不要写入源码或提交日志。

## 真实 A2UI 生成与动作

设置 `LIVE_UI_A2UI=1` 运行浏览器脚本，会请求模型调用 `render_a2ui`，点击本地卡片按钮并验证动作回传、同一界面数值更新以及刷新重放。

- 初次失败：模型没有可用的 render_a2ui。追查发现 OpenCode 回连本机 MCP 走了代理并收到 Privoxy 错误，而注册/连接 HTTP 仍返回成功。目录旧兼容接口同时返回 HTML；二者不能混同于没有任何工具。
- 本机服务启动必须给 **OpenCode 进程本身** 设置 `NO_PROXY=127.0.0.1,localhost`（必要时同时设置小写变量），仅设置浏览器或 Adapter 不足以覆盖上游 MCP 客户端。已重启本任务启动的 OpenCode/Adapter 后验证。
- 修复 Adapter：识别 V2 数组型 MCP 状态；只有实际 connected 才缓存注册结果，后续请求重新核验缓存，丢失连接会重建或报出明确错误。
- 真实会话 `ses_f8496a5b3ffeDCZqCBRsx3CiF8` 通过：生成计数 7 的界面、点击 live_confirm、真实动作请求、工具更新为 8、刷新后仍为 8。工具页显示 `mcp:agui_a2ui` 为 ready。

## 模型初始化恢复修复

- UI 查询最多自动尝试 3 次（间隔 0.5/1 秒），成功返回任一可用来源即可显示模型；列表为空时可使用服务返回的有效默认模型。持续失败后停止自动请求，显示错误及手动刷新入口。
- 切换会话/卸载会取消旧请求，加载时清除向输入组件传递的旧选择。手动刷新不清除草稿。
- `LIVE_UI_COLD=1` 让浏览器先访问页面再查询服务状态，不进行前置就绪等待。真实会话 `ses_f84208f35ffeyXSNZidkwYvj7f`：观察到一次空默认模型响应，页面无重载即恢复，随后实际发送和历史恢复通过。
- 该真实检查没有强制重启模型服务；可重复的空响应/持续失败/手动恢复边界由 `model-readiness.spec.ts` 控制响应验证。
